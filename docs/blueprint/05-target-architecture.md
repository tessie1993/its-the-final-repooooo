# 5 · Target architecture (Flutter + C++)

## 5.1 Principles

1. **Two languages for app code: Dart for UI and logic, C++ for anything on the audio, analysis, render or encode path.** A minimal Android host layer remains only where Android requires a JVM entry point (decision D1, doc 6).
2. **The C ABI is the contract.** `geode_api.h` stays the single boundary. Dart binds to it with `dart:ffi` (bindings generated by `ffigen`). There is no JNI and no MethodChannel on hot paths.
3. **Hot loops never cross into Dart.** Audio callbacks, analysis hops and render frames stay native. Dart sends commands (setters are already latched and thread-safe natively) and reads **snapshots** (a feature frame at roughly 10–30 Hz for meters, and the player position).
4. **The renderer owns its GL context.** C++ creates its own EGL context and render thread and draws into a window that Flutter composites through `Texture`. Widget rebuilds can't stall a frame.
5. **Contract-first.** Each new native module gets its `.hpp` contract and its `geode_*` C entry points before it is implemented.
6. **RAII everywhere.** Native handles are wrapped in Dart classes with a `NativeFinalizer` and an explicit `dispose()`. GL objects are already RAII natively.

## 5.3 Getting `AAssetManager` and a window without JNI glue code

- **Assets:** `geode_viz_create` needs an `AAssetManager*`. This is the one value that needs JNI: a 10-line static call from the Android host at start-up (`AAssetManager_fromJava`) that stores the pointer in the engine. The alternative is to copy `flutter_assets/shaders` to the cache dir on first run and read plain files, which removes JNI completely. **Recommendation: read plain files.** `ShaderSource` gets a file-system backend.
- **Surface:** Flutter's `TextureRegistry.SurfaceProducer` (Flutter ≥ 3.24) provides a `Surface`. A plugin-side call turns it into an `ANativeWindow*` (`ANativeWindow_fromSurface`) and passes it to `geode_surface_attach(window, w, h)`. The `RenderHost` then owns the EGL window surface, context and thread. Dart shows `Texture(textureId: id)`.

## 5.4 New C++ modules (replacing Kotlin hot paths)

| Module | Replaces (Kotlin) | Contract sketch |
|---|---|---|
| `host/PcmRing` | `PcmRingBuffer`, `SampleRing`, `AudioBus` | SPSC float ring with an absolute sample index + epoch. `read(fromIndex) → Ok/Gap/NotYetAvailable` (per `AUDIO_FEATURE_ABI.md`) |
| `host/AnalysisThread` | `AnalysisEngine`, `ReactiveAnalyzer` (live), `PulseHold`, `MidSideWindow` | Pulls from `PcmRing`, hop-locked `AnalysisSession::push/pull`, writes `FeatureRing` |
| `host/FeatureRing` | `FeatureRing` | Timestamped frames, `acquireAt(t)` with 5 outcomes + interpolation; the renderer reads it directly |
| `host/PresentationClock` | `AudioPresentationClock`, `ClockSegment`, `SinkClockDriver` | Input-sample ↔ presentation time over speed segments, using Oboe latency |
| `host/Engine` | `NativePlayer`, `NativePlayerDsp`, `NativeTapPump`, `PlaybackEngine` (engine part) | Wraps `Player` + DSP rebuild on rate change + the tap → `PcmRing`. Adds **time-stretch** (speed/pitch, e.g. vendored Signalsmith Stretch or SoundTouch, licence check) and **skip-silence**, which ExoPlayer used to provide |
| `host/CaptureSource` | `MicCapture`, `AudioCapturePump` | Oboe input stream → `PcmRing` (mic). Playback capture arrives from the SHIM through `geode_capture_write` |
| `host/RenderHost` | `VisualizerView`, `VisualizerRenderer` | EGL context + thread per `ANativeWindow`. Each frame: `FeatureRing.acquireAt(presentationTime)` → `geode_viz_set_features` → `geode_viz_render` → swap. Used by the app, the wallpaper, the dream and the second screen |
| `host/FramePacer` | `FramePacer`, `ThermalGovernor` (platform reads) | `AChoreographer_postFrameCallback64`, fps cap/divisor, `AThermal_getCurrentThermalStatus`/headroom → `geode_viz_set_thermal` |
| `host/OfflineAnalysis` | `OfflineAnalyzer`, `FrameAccumulator`, `AnalysisCache`, `FeatureTimeline`, `AiffPcm` | A job API with progress + cancel. Results are queryable (`timeline_at`, `transient_envelope`, `waveform`) |
| `host/export/*` | `VideoExporter`, `EncoderSurface`, `AudioTranscoder`, `LoopRender`, `LoopExtend`, `OffscreenSceneRenderer`, `LoudnessMeter`, `GlUtil` | `AMediaCodec` (H.264/HEVC + AAC) + `AMediaMuxer`. Offscreen `geode_viz` on a pbuffer/encoder input surface. BS.1770 meter |
| `host/export/Compositor` | Media3 Transformer path (`StudioExporter`, `ProjectComposition`, `ClipEdit`, `KeyframedClipEffects`, `GlTransitionEffect`, `SpeedRamp`, `TimedTextOverlay`) | Decode clips → GL effect chain (grade matrix, LUT 3D texture, rotation, transitions via the native `Transition`, caption RGBA) → encode. See decision D2 |

New C entry points: `geode_engine_*` (open/queue/transport/state snapshot), `geode_capture_*`,
`geode_surface_*`, `geode_analysis_job_*`, `geode_export_job_*`, and
`geode_features_snapshot(GeodeFeatureFrame*)` for UI meters.

## 5.5 Dart state: splitting `PlayerSession`

Graphify showed that `PlayerSession` has 185 symbols across about 20 controllers. Each
controller becomes its own Riverpod `Notifier`, with an explicit dependency graph and no god
object:

```
engineProvider (FFI handle, onDispose → destroy)
 ├─ playbackProvider ── queueProvider ── historyProvider ── sleepTimerProvider ── replayGainProvider
 ├─ captureProvider (mic / external)
 ├─ analysisProvider (job API, cache) ── autoVisualsProvider ── trackColorProvider
 ├─ vizProvider (scene, params, transitions, layers, background) ── modulationProvider (locks/undo/A-B/LFO/ADSR)
 │    └─ presetProvider · templateProvider · milkProvider · textureProvider · takeProvider
 ├─ libraryProvider (MediaStore/SAF scan, playlists, smart playlists, duplicates, tags)
 ├─ editorProvider (project + EditorHistory) ── exportProvider (jobs, ETA, loudness)
 └─ settingsProvider (prefs, theme pack, intent, safety ack)
```

Packages: `flutter_riverpod`, `go_router`, `freezed`/`json_serializable`, `ffigen`,
`shared_preferences`, `path_provider`, `permission_handler`, `file_picker` (SAF), and for the
D1 options `audio_service` + `home_widget`.

so history is kept.

## 5.7 Android manifest (Flutter host)

Carry over every permission from doc 1 §1.10 and **still no `INTERNET`**. In release builds,
remove the INTERNET permission Flutter adds by default, so the app stays offline. Keep the
activity flags for PiP and `configChanges`, the FileProvider, and the SHIM components chosen
under D1.
